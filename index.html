Token handling

How this single-file app treats sensitive values.

Browser storage is not secure storage. Anything stored in localStorage or sessionStorage is readable by scripts running on this origin. Credentials are kept in memory by default and are sent only to the documented endpoints (or to your configured reverse proxy).

Privacy & local data

Delete everything this app has stored in the browser.

Clearing removes credentials, tokens, PKCE state, account configuration and read markers from browser storage, and resets the in-memory session. It does not revoke Microsoft consent or delete server-side mailboxes.

Backend & browser requirements

Honest limits of a single static HTML file.

Reverse proxy (backend required): if api.dongvanfb.net or tools.dongvanfb.net does not return permissive CORS headers, a browser cannot call them directly. Configure the proxy base above; your backend must forward the original path, method, headers and body, and should hold the API key server-side. A static frontend cannot hide an API key, a client secret, or any server credential.
Microsoft Graph: direct browser calls work only with an Azure app registration whose redirect URI is configured as type Spa and delegated Mail.Read consent. This app uses PKCE, stores the access token in memory and refreshes it with offline_access when available. SPA refresh tokens have a limited lifetime; if refresh fails, sign in again.
Read state: Microsoft Graph messages include isRead; DONGVANFB responses do not document a read field, so no server read state is claimed for them. Opening a message never marks it read on the server — this app requests read-only mail permission. A small local marker only tracks what you have viewed in this browser.
